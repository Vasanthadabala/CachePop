**CachePop memory and performance audit — 13 November 2026**

The resource audit found and fixed a reproducible monitor retention problem, unnecessary background polling, overlapping disk reads, unbounded photo feature retention, command-output reader retention, and synchronous restoration work on the main actor. The fixes are in source and the local universal Release build. The existing public DMG has not been rebuilt for these changes.

The source inventory contains 77 Swift files across the app, shared SMC/protocol code and privileged fan helper. Review covered task/observer ownership, timers and polling, file enumeration, image decoding and caching, subprocess IO, fan XPC continuations, view-model cancellation and UI update paths. Earlier visual and functional changes remain in place.

| Area | Confirmed problem and fix |
| --- | --- |
| Monitor lifetime | The polling loop bound a strong `self` across each sleep, preventing release while polling remained active. It now uses short weak accesses, cancels on destruction and unregisters window observers. A regression failed against the original loop and passes after the fix. |
| Background sampling | Menu-bar-only polling collected detailed disk, network and battery data even when those details were not displayed. Basic polling now keeps CPU, memory, temperature and fan readings, while detailed IO/battery reads run for the visible System Monitor, Drive popover or recording. IO baselines reset after a long gap to avoid false throughput spikes. Memory SMC temperatures are read once per sensor per sample. |
| App/window ownership | Window-opening callbacks now capture the SwiftUI window action explicitly, avoiding a path from model to callback to view back to model. Periodic disk and settling tasks use weak references and cancel at destruction. |
| Disk refreshes | Repeated refreshes could launch detached disk-capacity queries that cancellation did not stop. Reads now coalesce into one active query and at most one pending follow-up. Fifty simultaneous requests require two actual reads in the regression. An OS disk query already in progress may still finish; another query is not launched over it. |
| Native menu popovers | Closed usage and fan popovers now release their hosting controllers. Controller destruction removes status items, mouse monitors, visibility observations and accessibility observers, stops fan animation, and balances monitor clients. Drive polling no longer retains its controller across the sleep. Fan labels and item widths update only when changed. The fan popover explicitly follows app appearance. |
| Photo feature memory | Photo analysis now feeds grouping in chronological order, retaining up to 40 comparison feature prints and no more than four pending/in-flight results. A slow image cannot cause an unlimited out-of-order buffer. Metadata needed for review remains proportional to the number of photos. |
| Image work and caches | Photo analysis runs at most four workers. Thumbnails use a 200-entry/32 MiB cache target with decoded byte costs; file icons use a 16 MiB target. A rescan invalidates the thumbnail generation, and disappearing photo tiles release their decoded images. Start Over clears photo thumbnails. Camera EXIF parsing reuses a formatter, and enumeration drains autoreleased objects per item. Cache limits are advisory, not strict app-memory limits. [Apple NSCache documentation](https://developer.apple.com/documentation/foundation/nscache/totalcostlimit). |
| File and app scanning | Cancellation propagates into app scans and catalog reads rather than leaving detached walks behind. Directory sizing and duplicate hashing check cancellation before opening or traversing more files. Disk Usage avoids duplicate measurements of the same folder and releases its tasks with the view model. Large Files clears previous scan/preview state and caches its sidebar total rather than reconstructing duplicate sets on unrelated live-reading updates. |
| Cancelled UI updates | Large Files, Photos and Clean Up scans use revision checks so late progress cannot update a replacement scan. Login Items reads agents and file-existence checks off the main actor, releases its model while waiting for the system list, and checks cancellation before changing remembered settings. Uninstalls cannot begin during an app scan, and background app-size results cannot repopulate a removed app's cache. |
| Subprocess resources | One nonblocking reader drains stdout and stderr with a combined output limit (16 MiB by default). Inherited pipes cannot leave blocked reader threads behind after timeout. All descriptors close and the owned child is stopped/reaped before the caller resumes; SIGKILL is used only for that child if SIGTERM fails. Read-only monitor commands stop on cancellation. |
| Battery health | The cached `system_profiler` request now uses the same bounded runner, with a five-second timeout, a 1 MiB output limit and cancellation. It no longer waits for termination before draining its output pipe. |
| Fan helper requests | Each XPC reply has a 15-second deadline and a single-resume gate. A stalled connection is invalidated so its disconnect fail-safe can release fans. Reply and timeout races cannot resume a continuation twice. Normal replies cancel the timer. |
| Permissions | The Full Disk Access fallback probes directory readability with `opendir`/one `readdir`, rather than allocating the entire Trash listing whenever the app activates. |
| Put Back responsiveness | Clean Up, Large Files and Photos perform restoration off the main actor. A second restore or rescan cannot overlap it. Existing destination checks and partial-failure reporting remain. Active cleanup/removal transactions retain their owner until reporting completes; they are finite operations, not abandoned polling loops. |

**Verification**

- **212 unit tests passed**, including 15 resource regressions. [Unit summary](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/build/resource-audit-unit-summary.json), [regression tests](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/CachePopTests/ResourceRegressionTests.swift).
- The monitor weak-reference regression failed before the loop fix and passed afterward. Saved logs: [baseline](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/build/resource-audit-runtime/monitor-leak-baseline.log), [fixed run](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/build/resource-audit-runtime/monitor-leak-fixed.log).
- A 5,000-photo grouping regression retains at most 41 synthetic feature objects during synchronous append, then releases every feature on completion. Another regression checks grouping equivalence with the original neighbour/time-window rules, including missing dates, missing features and transitive matches. This demonstrates feature-reference retention; it is not a measurement of an entire real Photos library's RAM usage.
- Command tests drain 4,000 lines from each stream, reject excessive output, handle inherited-pipe timeouts, and verify that a child ignoring SIGTERM is reaped.
- The compact all-sections UI test passed: cleanup review/confirmation/cancel, Large Files, Photos grouping, monitor details, Disk Usage drill-down, uninstall confirmation/cancel, Login Items, accessible settings controls, appearance switching and preserved scan state. [UI summary](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/build/resource-audit-ui-summary.json), [eight captures](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/build/resource-audit-ui-proof/manifest.json). The photo-review and monitor captures were visually inspected.
- The window-state-isolated fan UI test passed: visible rotor changes and centering, Custom/Full Speed/Automatic/Auto Boost through the demo controller, sensor/status details, recording and reopening System Monitor after Command-Q. [Fan UI summary](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/build/resource-audit-fan-ui-summary.json).
- The optimized Release app and bundled helper compile for **arm64 and x86_64**. No Swift compiler warnings were emitted by the final unit/Release runs. Xcode still emits its generic destination metadata diagnostic.
- A short idle Debug-process check, with a Memory menu item enabled, recorded **0.266% of one CPU core on average** over 30 seconds after a ten-second warm-up. RSS ranged from **84.27–84.80 MiB**. Window visibility was not recorded, so this is not a benchmark of an active monitor window, photo scan or cleanup. [Samples](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/build/resource-audit-runtime/samples.json).
- Apple's `leaks` tool reported **0 leaks / 0 leaked bytes** in that process. Its reported physical footprint was 26.7 MB, with a 75.6 MB startup peak. RSS and physical footprint are different measurements. This short snapshot cannot establish leak freedom for every workflow or a long-running session. [Leak report](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/build/resource-audit-runtime/leaks.txt).

**Remaining validation limits and follow-up**

The dedicated fan UI test initially could not start: an ordinary launch with only a native fan status item restored no main window. An explicit scene launch preference did not resolve it and was removed. Window-state-isolated interaction testing uses `-ApplePersistenceIgnoreState YES`, consistent with the main UI test. Ordinary native-only cold-launch recovery remains unresolved and should get a dedicated fix and test; it is not counted as fixed here.

Xcode also recorded a startup Security performance diagnostic: “This method should not be called on the main thread as it may lead to UI unresponsiveness.” The recorded stack contained addresses without usable symbols, and symbolication did not identify a responsible app call. It remains an investigation item; the passing UI flow does not justify calling that warning resolved.

Physical fan speeds and real login items were not changed. Intel code was compiled, with runtime checks performed on Apple silicon. Long-session Instruments allocation tracing, large real-library scans, slow external-volume restoration and installed-helper failure tests remain useful further coverage. Earlier functional follow-ups, including revalidating reviewed file identity before a Trash move, are recorded in the [12 November audit](/Volumes/Personal/Mac/Code/Work/MacOS/CachePop/docs/audits/2026-11-12-codebase-ui.md).
